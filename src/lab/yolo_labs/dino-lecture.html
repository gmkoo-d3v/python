01 · 파일 지도

이 파일은 누가 쓰나요?

먼저 큰 그림. common_dino.py는 “실행 파일”이 아니라 “부품 창고”입니다. 4일차 실습 5개가 여기서 부품을 꺼내 씁니다.

🍭 5살 비유

여러 명이 같이 쓰는 공용 반찬통 서랍이에요. 누군가 사진을 열어 놓으면, 다른 친구는 그 사진을 또 열 필요 없이 그냥 꺼내 쓰면 되죠. 서랍 위치(폴더)도 항상 같아서 헷갈리지 않아요.

이 파일을 직접 실행하면? 아무 일도 안 일어납니다. 맨 아래에 if __name__ == "__main__": 같은 실행 블록이 없거든요. 함수와 상수만 정의해 둔 라이브러리입니다. 다른 파일이 from common_dino import load처럼 불러다 씁니다.

  • 모델 이름·시드·사진 수를 한 번만 바꾸면 되게 하려고
  • 같은 특징을 여러 실습에서 재사용하려고

📢

부작용도 있어요. 이 설정은 이 프로세스 전체에 적용됩니다. 내 코드의 진짜 경고까지 같이 숨길 수 있으니, 디버깅할 때는 이 줄을 잠시 끄는 편이 좋습니다. category=UserWarning만 끄고, 에러(Error)는 끄지 않아요.

convnext_tiny.dinov3_lvd1689m. ViT가 아닌 ConvNeXt-Tiny 판, 약 2,780만 개 파라미터. 주석에 “20차시”라고 적혀 있고, lab21_small.py가 가져다 씁니다.

두 곳에서 쓰입니다. load()의 torch.manual_seed(SEED)(무작위 초기값 재현)와 eurosat()의 np.random.default_rng(SEED)(사진 섞기 재현). 서로 다른 난수 생성기라서 따로 설정합니다.

04 · pick_device()

어디서 계산할까? — 장치 고르기

모델과 텐서가 놓일 곳을 고릅니다. 빠른 곳이 있으면 빠른 곳, 없으면 차선, 그것도 없으면 CPU.

common_dino.py · 28–31행원문 그대로
def pick_device() -> torch.device:
    if torch.cuda.is_available():
        return torch.device("cuda")
    return torch.device("mps" if torch.backends.mps.is_available() else "cpu")

CUDA가 있나? NVIDIA GPU용. 있으면 바로 torch.device("cuda")를 돌려주고 함수 끝.

없으면 MPS가 있나? Apple Silicon(M1/M2/…)의 Metal Performance Shaders. 있으면 "mps".

둘 다 없으면 "cpu". 느리지만 어디서든 돌아감.

🔬 정확히는

반환값은 문자열이 아니라 torch.device 객체입니다. .to(pick_device())처럼 모델/텐서를 옮길 때 씁니다. 마지막 줄의 삼항 연산자는 CUDA가 없을 때만 평가됩니다. 즉 CUDA가 있으면 MPS는 검사조차 하지 않아요.

🎛️ 장치 선택 시뮬레이터

직접 눌러보기

아래 체크박스로 “이 컴퓨터에 무엇이 있는지”를 흉내 내 보세요. 함수가 어떤 장치를 돌려줄지 바로 보여줍니다.

반환값 → torch.device("cuda")

CUDA가 있으니 첫 번째 if에서 바로 반환합니다. MPS는 검사하지 않아요.

💡

내 컴퓨터에서 실제로 무엇이 잡히는지는 파이썬에서 torch.cuda.is_available()과 torch.backends.mps.is_available()을 직접 출력해 확인하면 됩니다. 이 페이지는 브라우저라서 실제 GPU를 볼 수 없어요.

🍭 5살 비유

엘리베이터(CUDA)가 있으면 엘리베이터를 타고, 없으면 에스컬레이터(MPS), 그것도 없으면 계단(CPU)으로 올라가는 거예요. 제일 빠른 것부터 확인합니다.

05 · load()

똑똑한 눈을 데려오기

DINOv3 모델을 만들고, 분류용 “이름표 기계”를 떼어 내고, 추론 모드로 세팅합니다.

common_dino.py · 34–37행원문 그대로
def load(name: str = MODEL, pretrained: bool = True) -> torch.nn.Module:
    """분류 머리 없이 특징만 내는 모델. pretrained=False면 같은 구조의 무작위 초기값(견줄 거리)."""
    torch.manual_seed(SEED)
    return timm.create_model(name, pretrained=pretrained, num_classes=0).eval().to(pick_device())

기본값은 name=MODEL, pretrained=True. 아무 인자 없이 load()라고 부르면 ViT-S/16 DINOv3가 옵니다.

시드 고정: torch.manual_seed(7). pretrained=False일 때 무작위 초기값을 항상 똑같이 만들기 위해서예요.

모델 생성: timm.create_model(name, pretrained=pretrained, num_classes=0). 이름을 주면 그 구조와 (원하면) 학습된 가중치를 만들어 줍니다.

분류 머리 제거: num_classes=0. “이 사진은 고양이”라고 이름표를 붙이는 마지막 층을 없앱니다. 대신 그 앞의 풍부한 특징 벡터가 출력됩니다.

추론 모드: .eval(). 드롭아웃을 끄고 BatchNorm이 학습 중 통계 대신 저장된 통계를 쓰게 합니다.

장치로 이동: .to(pick_device()). 모델의 모든 가중치를 GPU/MPS/CPU로 옮깁니다.

🔬 정확히는

일반 분류 모델은 특징 → (1000개 클래스 점수)로 끝납니다. num_classes=0이면 이 마지막 선형층이 사라져서 출력이 (배치, 특징 차원)이 됩니다. ViT-S/16 DINOv3는 384차원, ConvNeXt-Tiny는 768차원입니다. 정확한 값은 model.num_features로 확인할 수 있어요.

모델구조파라미터embed() 출력 차원쓰임
MODELViT-S/16약 2,160만384기본 특징 추출, 패치 특징
SMALLConvNeXt-Tiny약 2,780만768합성곱 구조 비교

🧠 학습된 눈 vs 무작위 눈

개념도

pretrained=False는 “모델을 안 만든다”가 아니라 같은 구조에 무작위 숫자를 넣는 것입니다. 구조는 같지만 세상을 배우지 않은 상태 — 좋은 비교 기준선이 됩니다.

학습된 특징은 사진의 구조를 따라 규칙적으로 변합니다. (개념을 위한 그림이지 실제 수치가 아니에요.)

⚠️ 함정
  • .eval()은 “가중치를 얼린다”가 아닙니다. 학습을 막으려면 torch.no_grad()나 옵티마이저를 안 쓰면 됩니다. eval()은 층의 동작 모드만 바꿔요.
  • manual_seed는 무작위 초기값 재현용. pretrained=True면 어차피 학습된 가중치를 덮어쓰므로 결과가 시드에 크게 흔들리지 않습니다.
  • timm은 처음 실행할 때 가중치를 내려받아 로컬 캐시에 둡니다. 인터넷이 필요할 수 있지만, 문서대로 Hugging Face 로그인은 필요 없어요.
  • load()는 모델을 학습하지 않습니다. 이미 학습된 눈을 그대로 빌려오는 것.
🍭 5살 비유

요리사에게 “이게 뭔지 이름 맞히기” 게임을 시키면, 요리사는 재료를 보고 이름표를 붙이죠. 우리는 이름표를 떼고 “이 재료는 이런 맛이야”라는 설명만 받는 거예요. 그 설명이 바로 특징 벡터입니다.

06 · _tensor()

사진을 모델이 먹는 모양으로 바꾸기

RGB로 맞추고, 크기를 바꾸고, 0~1로 나누고, 채널을 앞으로 옮기고, 평균·표준편차로 정규화합니다. 순서가 전부 중요해요.

common_dino.py · 40–47행원문 그대로
def _tensor(model: torch.nn.Module, images: list[Image.Image], size: tuple[int, int]) -> torch.Tensor:
    """사진을 정한 크기(높이, 너비)로 바꾸고 모델이 배운 평균·표준편차로 정규화한다."""
    cfg = model.pretrained_cfg
    mean = torch.tensor(cfg["mean"]).view(1, 3, 1, 1)
    std = torch.tensor(cfg["std"]).view(1, 3, 1, 1)
    arrays = [np.asarray(im.convert("RGB").resize((size[1], size[0]), Image.BICUBIC), np.float32) / 255 for im in images]
    x = torch.from_numpy(np.stack(arrays)).permute(0, 3, 1, 2)
    return ((x - mean) / std).to(pick_device())

전처리 레시피 꺼내기: model.pretrained_cfg에는 그 가중치가 학습될 때 쓴 평균·표준편차·크기·보간법이 들어 있습니다. 하드코딩하지 않고 모델에게 물어봅니다.

브로드캐스트 모양: 평균/표준편차를 (1, 3, 1, 1)로 바꿉니다. 배치 N과 공간 H·W에는 자동으로 퍼지고, 채널 3개에만 각각 적용되게 하려는 모양이에요.

RGB 강제: convert("RGB"). 흑백(1채널)이나 투명 PNG(4채널)가 와도 3채널로 맞춥니다.

크기 변경: resize((size[1], size[0]), Image.BICUBIC). 여기서 가로·세로 순서가 뒤집힙니다. 아래 함정 참고!

0~1로 나누기: / 255. 픽셀은 원래 0~255 정수인데, 모델은 0~1 실수를 기대합니다.

쌓기: np.stack(arrays) → (N, H, W, 3). 사진 N장을 한 덩어리로.

채널 앞으로: .permute(0, 3, 1, 2) → (N, 3, H, W). PyTorch는 채널이 앞에 오는 CHW를 좋아합니다. NumPy/PIL은 HWC였죠.

정규화 + 장치 이동: (x - mean) / std 후 .to(device). 모델이 배운 분포로 맞춰야 특징이 제대로 나옵니다.

⚠️ 대표 함정 — resize의 순서

size는 (높이, 너비)인데, PIL의 resize는 (너비, 높이)를 받습니다. 그래서 코드가 size[1], size[0]으로 일부러 뒤집어 넣어요. 이걸 놓치면 세로 사진이 가로로 찌그러집니다.

07 · embed()

사진 한 장 → 숫자 벡터 하나

이 파일의 심장. 여러 장을 배치로 나눠 계산하고, 각 벡터의 길이를 1로 맞춰 코사인 비교를 내적 한 번으로 만듭니다.

common_dino.py · 50–59행원문 그대로
@torch.no_grad()
def embed(model: torch.nn.Module, images: list[Image.Image], size: int | tuple[int, int] = 224,
          batch: int = 64) -> np.ndarray:
    """사진마다 특징 벡터 하나(길이 1로 맞춤). 코사인 유사도 = 내적. size는 정사각 한 변 또는 (높이, 너비)."""
    hw = (size, size) if isinstance(size, int) else size
    chunks = []
    for i in range(0, len(images), batch):
        feats = model(_tensor(model, images[i:i + batch], hw)).float().cpu().numpy()
        chunks.append(feats / np.linalg.norm(feats, axis=1, keepdims=True))
    return np.concatenate(chunks)

기울기 끄기: @torch.no_grad(). 우리는 학습이 아니라 추론만 하므로 역전파용 기록을 만들지 않습니다. 메모리와 시간을 아껴요.

기본값: size=224, batch=64. size는 정사각 한 변(int) 또는 (높이, 너비) 튜플.

정사각 처리: isinstance(size, int)면 (size, size)로. 튜플이면 그대로.

배치 루프: range(0, len(images), batch)로 0, 64, 128, … 잘라서 images[i:i+batch]만 모델에 넣습니다. 한 번에 다 넣으면 메모리가 터질 수 있어요.

모델 통과: model(_tensor(...)) → (배치, 특징 차원). 예: (64, 384).

NumPy로: .float()(fp16/bf16을 fp32로) → .cpu()(GPU에서 RAM으로) → .numpy().

길이 1로: feats / np.linalg.norm(feats, axis=1, keepdims=True). 각 행을 자기 L2 길이로 나눕니다.

합치기: np.concatenate(chunks) → (N, 384). 배치 크기와 무관하게 전체 사진의 특징이 나옵니다.

🔬 정확히는 — 코사인 = 내적
cos(a, b) = (a · b) / (‖a‖₂ · ‖b‖₂)
‖a‖₂ = √(a₁² + a₂² + … + aₙ²)
‖a‖₂ = ‖b‖₂ = 1 → cos(a, b) = a · b

그래서 embed()가 미리 모든 벡터를 단위 벡터로 만들어 둡니다. 그러면 실습에서는 test @ pool.T 같은 행렬 곱 한 번으로 모든 쌍의 코사인 유사도를 얻습니다. 값이 1에 가까울수록 같은 방향(비슷한 사진), 0이면 직각(무관), −1이면 반대 방향입니다.

08 · patch_tokens()

사진을 14×14 조각으로 나눠 보기

embed()가 사진 전체를 요약한 한 개의 벡터를 준다면, patch_tokens()는 조각마다 하나의 벡터를 줍니다. ViT 전용입니다.

common_dino.py · 62–67행원문 그대로
@torch.no_grad()
def patch_tokens(model: torch.nn.Module, image: Image.Image, size: tuple[int, int]) -> np.ndarray:
    """ViT의 패치마다 특징(높이/16 × 너비/16 × 384). 앞쪽의 CLS·레지스터 토큰은 뺀다."""
    tokens = model.forward_features(_tensor(model, [image], size))[0]
    patches = tokens[model.num_prefix_tokens:].float().cpu().numpy()
    return patches.reshape(size[0] // 16, size[1] // 16, -1)

한 장만: 인자도 image 한 장, 반환도 그 한 장의 패치 격자입니다. 배치 차원은 [0]으로 벗겨요.

forward_features: 분류 머리를 거치지 않고 토큰 시퀀스를 그대로 받습니다. model(x)가 요약 벡터를 주는 것과 다릅니다.

[0]: 배치 하나뿐이므로 첫 번째 샘플의 토큰들 → (토큰 수, 384).

앞 토큰 자르기: tokens[model.num_prefix_tokens:]. CLS 토큰과 레지스터 토큰을 뺍니다. 이 모델 구성에서는 보통 5개(CLS 1 + 레지스터 4)지만, 코드는 항상 모델에게 num_prefix_tokens를 물어봅니다.

격자로 재배열: reshape(H//16, W//16, -1). 224×224면 14 × 14 × 384.

🔬 정확히는

224×224 사진은 16×16 패치 196개로 나뉩니다. 각 패치 토큰은 384차원. 그래서 한 장당 196 × 384 = 75,264개의 숫자가 나옵니다. reshape의 16은 ViT의 패치 크기라서 patch16 모델 전용입니다. convnext_tiny(SMALL)에 이 함수를 쓰면 의도한 패치 격자가 나오지 않습니다.

⚠️ 함정
  • 16이 하드코딩되어 있습니다. patch16 ViT에서만 맞습니다.

  • 반환값은 (H/16, W/16, 384)이고, 앞 토큰은 이미 잘려 있습니다. embed() 출력과 모양이 완전히 다릅니다.
  • model.forward_features는 모델 종류마다 반환 형태가 다를 수 있습니다. 이 함수는 “ViT의 토큰 시퀀스”를 전제로 씁니다.

09 · pixels()

일부러 “멍청한” 기준선 만들기

DINOv3 특징이 정말 대단한지 보여주려면, 비교할 상대가 필요합니다. 그 상대가 바로 작게 줄인 원본 픽셀입니다.

common_dino.py · 70–74행원문 그대로
def pixels(images: list[Image.Image], side: int = 32) -> np.ndarray:
    """견줄 거리: 사진을 작게 줄인 픽셀값 그대로(길이 1로 맞춤)."""
    flat = np.stack([np.asarray(im.convert("RGB").resize((side, side)), np.float32).ravel() for im in images])
    flat -= flat.mean(axis=1, keepdims=True)
    return flat / np.linalg.norm(flat, axis=1, keepdims=True)

기본값 side=32. 모든 사진을 32×32로 줄입니다. 32×32×3 = 3,072차원.

펼치기: ravel()로 2D 이미지를 1D 벡터로. 행 우선(C order) 순서입니다.

밝기 빼기: flat -= flat.mean(axis=1, keepdims=True). 사진마다 평균을 빼서 “전체적으로 밝은 사진”이 유리하지 않게 합니다.

길이 1로: L2 정규화. embed()와 같은 이유 — 코사인 = 내적.

🔬 정확히는 — 여기엔 /255가 없어요

_tensor()는 /255를 하지만 pixels()는 하지 않습니다. 픽셀 값은 0~255 그대로 float32가 됩니다. 그래도 평균을 빼고 L2 정규화를 하기 때문에, 코사인 유사도 기준으로는 전체 스케일이 결과에 영향을 주지 않습니다. 다만 유클리드 거리를 쓰면 스케일이 달라지니 주의하세요.

왜 기준선이 필요할까? “DINO가 90% 맞혔어요”만으로는 잘한 건지 알 수 없습니다. “픽셀만 보면 60%, DINO는 90%”라고 해야 학습된 특징의 가치가 보입니다. lab18/lab19가 pixels를 가져가는 이유예요.

⚠️ 함정
  • resize((side, side))는 정사각이라 PIL의 (너비, 높이) 순서 문제가 없습니다.
  • ravel()은 채널 순서까지 그대로 펼칩니다. RGB 순서가 바뀌면 벡터도 바뀝니다.
  • 픽셀 기준선은 회전·이동·색 변환에 매우 약합니다. 이게 바로 DINO 특징과의 차이를 보여주는 포인트.
  • 사진마다 평균을 빼므로 “평균 밝기” 정보는 사라집니다. 의도된 동작입니다.

10 · eurosat()

위성사진을 “연습장”과 “시험지”로 나누기

EuroSAT에서 클래스마다 50장은 라벨을 볼 수 있는 pool로, 100장은 정답을 숨긴 test로 뽑습니다. 같은 사진이 양쪽에 들어가면 반칙이에요.

common_dino.py · 77–90행원문 그대로
def eurosat() -> tuple[list[Image.Image], np.ndarray, list[Image.Image], np.ndarray, list[str]]:
    """EuroSAT(위성사진 10종, 64×64, MIT 라이선스)에서 클래스마다 고를 거리 50장, 시험 100장을 뽑는다."""
    from torchvision.datasets import EuroSAT
    ds = EuroSAT(str(DATA), download=not (DATA / "eurosat" / "2750").exists())
    labels = np.array(ds.targets)
    rng = np.random.default_rng(SEED)
    pool_idx, test_idx = [], []
    for c in range(len(ds.classes)):
        idx = rng.permutation(np.nonzero(labels == c)[0])
        pool_idx += idx[:POOL_PER_CLASS].tolist()
        test_idx += idx[POOL_PER_CLASS:POOL_PER_CLASS + TEST_PER_CLASS].tolist()
    load_image = lambda i: Image.open(ds.samples[i][0]).convert("RGB")
    return ([load_image(i) for i in pool_idx], labels[pool_idx],
            [load_image(i) for i in test_idx], labels[test_idx], ds.classes)

지연 import: from torchvision.datasets import EuroSAT가 함수 안에서 실행됩니다. 이 파일을 import할 때는 torchvision이 없어도 되고, 실제로 데이터를 뽑을 때만 필요합니다.

다운로드 판단: download=not (DATA / "eurosat" / "2750").exists(). data/eurosat/2750 폴더가 이미 있으면 download=False, 없으면 True.

라벨 배열: labels = np.array(ds.targets). 사진마다 0~9 정수.

재현 가능한 섞기: np.random.default_rng(SEED). NumPy의 새 난수 생성기. torch.manual_seed와 별개입니다.

클래스별 순회: for c in range(len(ds.classes)). 0번부터 9번까지.

그 클래스의 인덱스만: np.nonzero(labels == c)[0] → 섞기(rng.permutation).

앞 50장 = pool: idx[:POOL_PER_CLASS]. 뒤 100장 = test: idx[50:150]. 나머지는 버립니다.

사진 열기: Image.open(ds.samples[i][0]).convert("RGB"). ds.samples[i]는 (경로, 라벨)이라 [0]이 경로.

반환 순서: (pool 사진, pool 라벨, test 사진, test 라벨, 클래스 이름). 이 순서를 헷갈리면 라벨이 사진과 어긋납니다.

"""4일차(DINOv3) 공통 부분: 모델 불러오기, 특징 뽑기, EuroSAT 나누기.

Built with DINOv3. 가중치는 Meta의 DINOv3 License를 따릅니다
(https://ai.meta.com/resources/models-and-libraries/dinov3-license/).
timm에 올라온 가중치를 쓰므로 Hugging Face 로그인 없이 받아집니다.
"""

import warnings
from pathlib import Path

warnings.filterwarnings("ignore", category=UserWarning)

import numpy as np
import timm
import torch
from PIL import Image

HERE = Path(__file__).resolve().parent
DATA = HERE / "data"
OUT = HERE / "runs" / "dino"
MODEL = "vit_small_patch16_dinov3.lvd1689m"      # ViT-S/16, 2,160만 파라미터
SMALL = "convnext_tiny.dinov3_lvd1689m"          # 합성곱 판, 2,780만 파라미터(20차시)
SEED = 7
POOL_PER_CLASS = 50     # 라벨을 고를 수 있는 사진(클래스마다)
TEST_PER_CLASS = 100    # 시험 사진(클래스마다)


def pick_device() -> torch.device:
    if torch.cuda.is_available():
        return torch.device("cuda")
    return torch.device("mps" if torch.backends.mps.is_available() else "cpu")


def load(name: str = MODEL, pretrained: bool = True) -> torch.nn.Module:
    """분류 머리 없이 특징만 내는 모델. pretrained=False면 같은 구조의 무작위 초기값(견줄 거리)."""
    torch.manual_seed(SEED)
    return timm.create_model(name, pretrained=pretrained, num_classes=0).eval().to(pick_device())


def _tensor(model: torch.nn.Module, images: list[Image.Image], size: tuple[int, int]) -> torch.Tensor:
    """사진을 정한 크기(높이, 너비)로 바꾸고 모델이 배운 평균·표준편차로 정규화한다."""
    cfg = model.pretrained_cfg
    mean = torch.tensor(cfg["mean"]).view(1, 3, 1, 1)
    std = torch.tensor(cfg["std"]).view(1, 3, 1, 1)
    arrays = [np.asarray(im.convert("RGB").resize((size[1], size[0]), Image.BICUBIC), np.float32) / 255 for im in images]
    x = torch.from_numpy(np.stack(arrays)).permute(0, 3, 1, 2)
    return ((x - mean) / std).to(pick_device())


@torch.no_grad()
def embed(model: torch.nn.Module, images: list[Image.Image], size: int | tuple[int, int] = 224,
          batch: int = 64) -> np.ndarray:
    """사진마다 특징 벡터 하나(길이 1로 맞춤). 코사인 유사도 = 내적. size는 정사각 한 변 또는 (높이, 너비)."""
    hw = (size, size) if isinstance(size, int) else size
    chunks = []
    for i in range(0, len(images), batch):
        feats = model(_tensor(model, images[i:i + batch], hw)).float().cpu().numpy()
        chunks.append(feats / np.linalg.norm(feats, axis=1, keepdims=True))
    return np.concatenate(chunks)


@torch.no_grad()
def patch_tokens(model: torch.nn.Module, image: Image.Image, size: tuple[int, int]) -> np.ndarray:
    """ViT의 패치마다 특징(높이/16 × 너비/16 × 384). 앞쪽의 CLS·레지스터 토큰은 뺀다."""
    tokens = model.forward_features(_tensor(model, [image], size))[0]
    patches = tokens[model.num_prefix_tokens:].float().cpu().numpy()
    return patches.reshape(size[0] // 16, size[1] // 16, -1)


def pixels(images: list[Image.Image], side: int = 32) -> np.ndarray:
    """견줄 거리: 사진을 작게 줄인 픽셀값 그대로(길이 1로 맞춤)."""
    flat = np.stack([np.asarray(im.convert("RGB").resize((side, side)), np.float32).ravel() for im in images])
    flat -= flat.mean(axis=1, keepdims=True)
    return flat / np.linalg.norm(flat, axis=1, keepdims=True)


def eurosat() -> tuple[list[Image.Image], np.ndarray, list[Image.Image], np.ndarray, list[str]]:
    """EuroSAT(위성사진 10종, 64×64, MIT 라이선스)에서 클래스마다 고를 거리 50장, 시험 100장을 뽑는다."""
    from torchvision.datasets import EuroSAT
    ds = EuroSAT(str(DATA), download=not (DATA / "eurosat" / "2750").exists())
    labels = np.array(ds.targets)
    rng = np.random.default_rng(SEED)
    pool_idx, test_idx = [], []
    for c in range(len(ds.classes)):
        idx = rng.permutation(np.nonzero(labels == c)[0])
        pool_idx += idx[:POOL_PER_CLASS].tolist()
        test_idx += idx[POOL_PER_CLASS:POOL_PER_CLASS + TEST_PER_CLASS].tolist()
    load_image = lambda i: Image.open(ds.samples[i][0]).convert("RGB")
    return ([load_image(i) for i in pool_idx], labels[pool_idx],
            [load_image(i) for i in test_idx], labels[test_idx], ds.classes)


def cached(name: str, make) -> np.ndarray:
    """오래 걸리는 특징 뽑기는 runs/dino에 저장해 두고 다시 쓴다."""
    path = OUT / f"{name}.npy"
    if path.exists():
        return np.load(path)
    OUT.mkdir(parents=True, exist_ok=True)
    value = make()
    np.save(path, value)
    return value

15 · 용어 사전

        
막히면 여기로

        
이 페이지에 나온 용어를 한곳에 모았습니다. 접어 두었으니 필요한 것만 펼쳐 보세요.

      


      
임베딩 / 특징 벡터 (embedding / feature vector)
사진·글 같은 복잡한 대상을 숫자 여러 개의 나열로 바꾼 것. DINOv3 ViT-S/16은 사진 한 장을 384개 숫자로 요약합니다. 의미가 비슷한 대상은 벡터도 가까워지도록 학습됩니다.

      
ViT (Vision Transformer)
이미지를 16×16 패치로 자르고, 각 패치를 문장의 단어 토큰처럼 처리하는 신경망 구조. 패치들 사이의 관계를 attention으로 계산합니다.

      
패치 (patch)
ViT가 이미지를 자르는 작은 조각. patch16은 한 변이 16픽셀이라는 뜻입니다. 224×224 → 14×14 = 196개.

      
CLS 토큰
ViT 맨 앞에 붙는 특별한 토큰. 패치 정보를 모아 사진 전체를 요약하는 역할을 합니다. tokens[0]에 해당하며, patch_tokens()는 이 토큰을 잘라냅니다.

      
레지스터 토큰 (register token)
CLS 토큰과 함께 앞쪽에 붙는 보조 토큰. attention이 특정 패치에 과도하게 몰리는 현상을 줄이는 데 도움을 줍니다. DINOv2/v3 계열에서 사용됩니다. 앞 토큰 전체 개수는 model.num_prefix_tokens로 확인합니다.

      
파라미터 (parameter)
모델 안에서 학습으로 조정되는 숫자. ViT-S/16 DINOv3는 약 2,160만 개, ConvNeXt-Tiny는 약 2,780만 개. “2,160만”은 저장 용량/계산량 감각을 주는 지표입니다.

      
pretrained / 사전학습
큰 데이터로 미리 학습해 둔 상태. pretrained=True는 그 지식을 가져오고, False는 같은 구조에 무작위 숫자를 넣어 비교 기준선으로 씁니다.

      
추론 (inference)
학습이 끝난 모델로 답을 계산하는 것. 이 파일의 모든 특징 추출은 추론입니다. 그래서 torch.no_grad()를 씁니다.

      
텐서 (tensor)
PyTorch의 다차원 숫자 배열. 사진 배치는 (N, C, H, W) 모양을 씁니다. NumPy 배열과 비슷하지만 GPU로 옮길 수 있고 자동 미분을 지원합니다.

      
정규화 (normalization)
값의 범위나 분포를 일정하게 맞추는 것. 여기서는 (x − mean) / std로 채널별 표준화를 합니다. 모델이 학습할 때 본 분포와 맞추는 것이 목적입니다.

      
L2 노름 / 단위 벡터
벡터의 길이 ‖v‖₂ = √(v₁²+…+vₙ²). 벡터를 자기 길이로 나누면 길이가 1인 단위 벡터가 됩니다. embed()가 이렇게 합니다.

      
코사인 유사도 (cosine similarity)
두 벡터가 이루는 각도의 코사인. (a·b)/(‖a‖‖b‖). 1에 가까우면 같은 방향, 0이면 직각, −1이면 반대. 단위 벡터끼리는 내적과 같습니다.

      
내적 (dot product)
a·b = a₁b₁ + a₂b₂ + …. NumPy에서는 a @ b 또는 np.dot. 행렬에서는 test @ pool.T로 모든 쌍의 유사도를 한 번에 계산합니다.

      
시드 (seed)
난수 생성기의 시작 번호. 같은 시드면 같은 순서의 “무작위”가 재현됩니다. 여기서는 SEED=7을 torch 초기화와 NumPy 데이터 섞기에 각각 사용합니다.

      
배치 (batch)
한 번에 모델에 넣는 샘플 묶음. 메모리를 아끼려고 64장씩 나눕니다. 배치 크기는 결과를 바꾸지 않고 속도/메모리만 바꿉니다.

      
torch.no_grad()
자동 미분 기록을 끄는 컨텍스트. 추론에서 메모리를 크게 아낍니다. model.eval()과 역할이 다릅니다 — 하나는 층 모드, 하나는 기울기 기록.

      
eval 모드
model.eval()로 설정. 드롭아웃을 끄고 BatchNorm이 running statistics를 쓰게 합니다. 학습 중 통계가 섞이지 않아 추론이 결정적이 됩니다.

      
캐시 (cache)
비싼 계산 결과를 파일에 저장해 두고 재사용하는 것. 여기서는 runs/dino/<name>.npy. 이름이 키이므로 조건이 바뀌면 반드시 이름을 바꾸거나 파일을 지워야 합니다.

      
EuroSAT
유럽 위성사진 분류 데이터셋. 10개 클래스, 64×64 픽셀, MIT 라이선스, 약 27,000장. 이 파일은 클래스당 50장(pool) + 100장(test)만 사용합니다.

      
분류 머리 (classification head)
특징 벡터를 클래스 점수로 바꾸는 마지막 층. num_classes=0이면 이 층이 사라져 특징만 나옵니다. “이름표 기계를 떼어 낸다”고 생각하면 쉽습니다.

      
forward_features
timm 모델에서 분류 머리를 건너뛰고 중간 특징(토큰 시퀀스 또는 특징 맵)을 반환하는 메서드. patch_tokens()가 이걸 써서 패치별 토큰을 얻습니다.

      
NumPy 배열 (ndarray)
다차원 숫자 배열. embed(), pixels(), patch_tokens()의 반환형입니다. PyTorch 텐서와 달리 GPU에 있지 않고, .npy로 저장할 수 있습니다.
