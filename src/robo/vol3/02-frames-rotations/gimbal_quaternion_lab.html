THE IDEA BEHIND THE MOTION
01 / EULER ANGLES

각도 세 개 + 순서 하나

“어느 축으로 얼마나 돌릴까”를 적는 방법입니다. 각도만 같아도 축의 순서가 다르면 결과가 달라집니다.[1]

02 / GIMBAL LOCK

물체가 아니라, 표현이 막힌다

특정 자세에서 첫째와 셋째 조작축이 같은 직선에 놓입니다. 두 조작이 겹쳐 순간적으로 독립인 회전 방향이 하나 줄어듭니다.[2][4]

03 / QUATERNION

네 숫자로 자세를 저장한다

회전축과 회전각을 함께 담는 단위 쿼터니언을 사용합니다. 숫자는 네 개지만 길이 1이라는 제약이 있어 회전 자유도는 여전히 세 개입니다.[5]

왜 하필 90°에서 두 조작이 겹칠까?

이 실험의 규약은 내재 회전(intrinsic rotation) Z → Y′ → X″입니다. 프라임(′, ″)은 앞선 회전을 따라 축이 이미 움직였다는 표시예요. 열벡터에 작용하는 최종 회전행렬은 다음과 같습니다.

R = Rz(ψ) · Ry(θ) · Rx(φ) φ = roll, θ = pitch, ψ = yaw

고리의 연결 순서는 바깥 Z, 가운데 Y′, 안쪽 X″입니다. 행렬을 한 벡터에 곱할 때 오른쪽부터 계산하는 것과, 고리를 바깥부터 연결하는 것은 구분해야 합니다.

월드 좌표로 본 세 조작축은 다음과 같습니다.

aψ = (0, 0, 1) aθ = Rz(ψ) · (0, 1, 0) aφ = Rz(ψ) · Ry(θ) · (1, 0, 0) θ = +90° → aφ = −aψ θ = −90° → aφ = +aψ

+90°에서는 요를 +15°, 롤도 +15° 바꾸면 서로 반대 방향의 회전이 상쇄됩니다. 두 숫자가 바뀌어도 자세는 같아요. −90°에서는 요 +15°, 롤 −15°가 상쇄됩니다. 같은 직선에서 반대 방향인 축도 독립적인 새 방향은 아닙니다.

자유도 감소는 “순간적인” 이야기입니다

야코비안(Jacobian)은 “손잡이 속도”를 “물체의 회전속도”로 바꾸는 표입니다. 이 표의 서로 독립인 방향 수를 rank라고 합니다.

ω = [aψ aθ aφ] · (ψ̇, θ̇, φ̇)ᵀ |det J| = |cos θ| θ = 89° → rank 3 · 불안정한 근접 상태 θ = 90° → rank 2 · 정확한 특이점

피치를 바꾸어 특이점 밖으로 나갈 수 있습니다. 물체의 모든 회전이 영원히 막힌 것이 아닙니다. 또 물체 자체의 X·Y·Z 좌표축은 계속 직교합니다. 겹치는 것은 서로 다른 단계의 조작축이에요. 오일러 각으로 다시 분해할 때는 첫째·셋째 각을 유일하게 정할 수 없어집니다.[4]

쿼터니언의 x, y, z, w는 무엇일까?

쿼터니언(quaternion, 사원수)은 네 성분을 가진 수 체계입니다. 여기서는 그중 길이가 1인 것만 골라 3D 자세를 나타냅니다.

먼저 길이 1인 회전축 u = (uₓ, uᵧ, u𝓏)를 고릅니다. 그 축으로 α만큼 돌리는 회전을 다음 네 숫자로 적습니다.[5]

x = uₓ · sin(α/2) y = uᵧ · sin(α/2) z = u𝓏 · sin(α/2) w = cos(α/2) x² + y² + z² + w² = 1

x·y·z는 위치도, 롤·피치·요도 아닙니다. 회전축 방향에 sin(α/2)를 곱한 값입니다. w도 “네 번째 공간축”이 아니라 cos(α/2)라는 스칼라 값이에요.

Y축으로 90° 회전 u = (0, 1, 0), α/2 = 45° q ≈ (0, 0.7071, 0, 0.7071)

왜 각도의 절반이 들어갈까?

벡터를 회전할 때는 순허수 쿼터니언 p = (vₓ, vᵧ, v𝓏, 0)로 만든 뒤 p′ = q · p · q⁻¹처럼 양쪽에서 곱합니다. 이 연산을 전개하면 cos α, sin α가 나와 실제 회전각 α가 됩니다. 그래서 q 자체에는 반각 α/2가 들어갑니다.

q와 −q는 같은 자세입니다

네 성분의 부호를 모두 뒤집어도 회전 결과는 같습니다. 위 연산에서 두 마이너스 부호가 상쇄되기 때문입니다. 실험 03의 부호 뒤집기 버튼으로 확인할 수 있어요.[5]

단, 쿼터니언은 기계의 고리 배치를 바꾸지 않습니다. 물리적인 짐벌의 특이점을 없애 주는 장치가 아니라, 소프트웨어에서 자세를 저장하고 합성할 때 오일러 각의 특이점을 피하는 표현입니다.

Three.js 코드에서 무엇을 바꿔야 할까?

Three.js의 rotation은 오일러 각, quaternion은 쿼터니언입니다. 두 속성은 연결되어 있습니다. 이 실험은 Three.js가 연결되면 아래의 쿼터니언 연산과 WebGL 렌더링을 사용합니다.[2][3]

01 · 출발 자세 만들기
const rad = THREE.MathUtils.degToRad;

// 생성자 인자는 항상 x, y, z 순서입니다.
// 'ZYX'는 적용할 회전 순서입니다.
const euler = new THREE.Euler(
  rad(roll), rad(pitch), rad(yaw), 'ZYX'
);
mesh.quaternion.setFromEuler(euler);
02 · 추가 회전은 쿼터니언으로 합성
const delta = new THREE.Quaternion()
  .setFromAxisAngle(
    new THREE.Vector3(1, 0, 0),
    THREE.MathUtils.degToRad(15)
  );

// mesh의 부모에 회전이 없다는 조건입니다.
// 고정된 월드 X축으로 추가 회전
mesh.quaternion.premultiply(delta);

// 물체 자신의 X축 기준이라면 대신:
// mesh.quaternion.multiply(delta);

mesh.quaternion.normalize();

주의: 값을 한 번 쿼터니언으로 바꿔 놓고 이후에도 롤·피치·요 세 각도만 계속 더하면 입력 방식의 특이점은 남습니다. 현재 q를 상태로 보관하고 증분 회전 Δq를 곱해야 합니다. 오일러 각으로 다시 표시할 때는 각도가 뛰거나 유일하지 않을 수 있어요.[4]

또한 회전된 부모 아래의 객체라면 mesh.quaternion은 부모 기준 자세입니다. 위의 “월드 축” 예제를 그대로 쓰지 말고 월드 회전축을 부모 좌표계로 변환해야 합니다.

03 · 두 자세 사이 보간
// 매 프레임 출발 qA에서 계산합니다.
// 직전 결과를 다시 출발점으로 삼지 않습니다.
mesh.quaternion.slerpQuaternions(qA, qB, t);
// t=0: 출발, t=1: 도착

쿼터니언 곱도 순서를 바꾸면 결과가 달라집니다. qA × qB ≠ qB × qA가 일반적입니다. 짐벌락을 피한다는 말이 “회전 순서가 사라진다”는 뜻은 아닙니다.

SLERP는 무엇이며, 언제 유용할까?

보간(interpolation)은 출발과 도착 사이의 중간 상태를 채우는 일입니다. SLERP는 Spherical Linear Interpolation의 약자로, 단위 쿼터니언 사이를 구면 위에서 보간합니다.

실험 04의 첫 예에서는 +170°와 −170°가 숫자로는 340° 떨어져 있지만, 실제 자세는 20°만 다릅니다. 각도 숫자를 그대로 섞으면 0°를 거쳐 크게 돌아갑니다. SLERP는 q와 −q가 같은 자세라는 점까지 고려해 짧은 경로를 고릅니다.[5][6]

각도 선형 보간: 170° → 0° → −170° SLERP: 170° → 180° → 190° ≡ −170°

여기서 표시한 SLERP의 190°는 경로 이해를 돕는 연속 각도입니다. 저장된 오일러 각을 다시 읽으면 −170° 등 다른 대표값으로 표시될 수 있습니다.

두 단위 쿼터니언의 내적을 양수로 맞춘 뒤, Ω = acos(q₀·q₁)라 두면 다음과 같이 보간합니다. 여기서 Ω는 쿼터니언 공간의 각도이며 실제 상대 회전각은 2Ω입니다.

slerp(q₀,q₁,t) = sin((1−t)Ω)/sin Ω · q₀ + sin(tΩ)/sin Ω · q₁

t가 시간에 따라 일정하게 증가하면 한 구간에서 회전의 각속도도 일정합니다.[6] Ω가 거의 0이면 0으로 나누는 수치 문제를 피하기 위해 정규화된 선형 보간으로 처리합니다.

짐벌락과 구별하세요. ±180° 경계는 각도 대표값의 불연속 문제입니다. 정확한 짐벌락은 회전속도에 대한 오일러 좌표의 특이점입니다. 이들은 관련은 있지만 같은 현상은 아닙니다.

여러 바퀴 도는 애니메이션은 시작·끝 자세 두 개만으로 회전 횟수를 복원할 수 없습니다. 중간 키프레임이나 누적 회전량을 따로 지정해야 합니다. 여러 SLERP 구간을 이어도 경계에서 각속도 방향까지 매끄럽다고 보장되지는 않습니다.

외부 연결이 가능하면 고정 버전 Three.js 0.180.0을 jsDelivr 또는 unpkg에서 불러옵니다. 네트워크 또는 WebGL이 사용할 수 없으면 같은 기하와 수학을 사용하는 내장 Canvas 원근 투영 렌더러로 동작합니다. 화면 오른쪽 아래에 실제 엔진이 표시됩니다. 해설·조작·수학 계산은 네트워크 없이도 동작합니다.

외부 요청은 라이브러리 다운로드뿐이며, 입력값 전송·분석 추적·로그인은 없습니다. 참고 링크를 열 때에는 인터넷이 필요합니다. 3D 장면은 개념 설명용으로 직접 구성했으며 기계적인 관절 한계·충돌·동역학은 시뮬레이션하지 않습니다.

검증: 단위 쿼터니언 계산과 짐벌락 조건에 대한 자동 테스트를 포함합니다. 작성 환경에서는 외부 라이브러리 다운로드가 차단되어 내장 렌더러 경로를 브라우저로 검증했습니다. Three.js WebGL 경로는 해당 환경에서 실제 구동하지 못했습니다.
